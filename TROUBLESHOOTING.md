# Troubleshooting

## Бот не отвечает в чате

### Симптом
Бот в чате, но не реагирует на сообщения, не удаляет спам.

### Проверь

1. **Privacy Mode в BotFather выключен**
   `/mybots` → `@asvet_probot` → Bot Settings → Group Privacy → Turn off
   По умолчанию бот в группе видит только `/command@bot` и упоминания. Без выключения бот не видит обычные сообщения и не может фильтровать спам.

2. **Бот — админ чата с нужными правами**
   Права: «Удалять сообщения» + «Блокировать пользователей». Без них бот не сможет удалять и кикать.

3. **CHAT_ID совпадает**
   `/id` в чате (от имени админа) покажет реальный `chat.id`. Должен совпадать с `CHAT_ID` в `.env`.

## `result: []` в `getUpdates`

Значит бот не получает апдейты. Причины:

- Бот не добавлен в чат
- Privacy Mode включён (см. выше)
- В чате нет новых сообщений (бот видит только новые, не историю)
- В `getUpdates` смотришь с другим токеном, нежели у бота

## Ошибка в логах: `BOT_TOKEN не задан`

`BOT_TOKEN` пустой или отсутствует в `.env`. Проверь:
- Файл лежит в корне проекта (рядом с `pyproject.toml`)
- Бот запускается **из этой папки** (cwd важен)
- В строке нет кавычек вокруг значения

## `re.error: missing ), unterminated subpattern`

Битый regex в `BANNED_PATTERNS`. Проверь:
- Каждый паттерн — самостоятельный regex, не оборачивай в `(?i)(...|...|...)`
- Паттерны разделяются `||` (двойной пайп), не одинарным
- Файл `.env` сохранён в UTF-8 (не cp1251 / Windows-1251)
- Скобки сбалансированы внутри каждого паттерна

## `sqlite3.OperationalError: unable to open database file`

Бот не может создать/открыть `data/bot.db`. Проверь:
- Папка `data/` существует и доступна на запись
- В Docker-окружении смонтирован volume в `/app/data`
- Путь в `DB_PATH` указывает туда, куда смонтирован volume

## `TelegramForbiddenError: bot was kicked`

Бот был удалён из чата или потерял права. Решения:
- Добавь бота обратно
- Проверь, что он остался админом
- Если бот сам себя кикнул (например, ложный бан) — посмотри `data/bot.db`, найди запись в `bans`, удали через `db.unban()`

## Бот удаляет нормальные сообщения

Спам-фильтр слишком жадный. Варианты:
- Посмотри в логах, какой именно паттерн сработал (`паттерн ...`)
- Убери или уточни проблемный паттерн в `BANNED_PATTERNS`
- Добавь «жертву» в белый список: `/whitelist_add @user`

## `BANNED_PATTERNS` ловит ссылки, но пропускает спам без ссылок

Это нормально — паттерны срабатывают по regex, а не «умному» анализу. Для критичных случаев добавь в `BANNED_PATTERNS` конкретные слова/фразы.

## Два бота в одном чате

Если случайно запустил две копии (локально + Coolify), обе получают все апдейты и фильтруют сообщения параллельно. Останови одну из копий.

## Бот молчит после перезапуска

- Подожди 5–10 секунд — `start_polling` восстанавливает соединение
- Если не помогло — посмотри логи на наличие `aiogram.exceptions`
- Проверь, не съел ли systemd/Coolify SIGTERM без корректного завершения (в БД могут остаться `captchas` с уже истекшим `deadline` — sweeper их подчистит)

## Как посмотреть, что в БД

```bash
sqlite3 data/bot.db
> .tables
> SELECT * FROM bans;
> SELECT * FROM stats;
> .quit
```

В Coolify — открой shell контейнера (Exec) и выполни то же.

## Нужен полный сброс

```bash
# Остановить бота, удалить БД, запустить заново
rm data/bot.db
uv run python -m bot
```

Все баны, вайтлист, счётчики — обнулятся. Полезно при тестах.

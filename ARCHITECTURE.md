# Архитектура бота

## Общая картина

```
                 ┌──────────────────────────┐
   Telegram ◀──▶ │  aiogram Dispatcher      │
   (long poll)   │  ├── middleware (deps)   │
                 │  ├── captcha router      │
                 │  ├── messages router     │
                 │  └── admin router        │
                 └────────────┬─────────────┘
                              │
                  ┌───────────┴───────────┐
                  │                       │
            ┌─────▼──────┐         ┌──────▼──────┐
            │  filters   │         │   db.py     │
            │  ├ flood   │         │  (aiosqlite)│
            │  ├ spam    │         └──────┬──────┘
            │  ├ new_acc │                │
            │  └ admin   │           SQLite: bot.db
            └────────────┘
```

Бот — один long-polling процесс. Очередей нет, воркеров нет, горизонтального масштабирования нет. Рассчитан на один инстанс.

## Структура папок

```
bot/
├── __main__.py          # entrypoint + DI
├── config.py            # .env → Settings dataclass (с валидацией)
├── db.py                # все SQL-запросы, класс Database
├── texts.py             # все пользовательские строки (легко локализовать)
├── filters/             # чистые функции-проверки (без side-effects)
│   ├── new_account.py   # оценка возраста по user_id
│   ├── flood.py         # счётчик сообщений в окне
│   ├── spam.py          # regex-матчер
│   └── admin.py         # проверка, в списке ли ADMIN_IDS
├── handlers/            # aiogram-роутеры
│   ├── captcha.py       # вступление + кнопка + sweeper
│   ├── messages.py      # антифлуд + спам-фильтр
│   └── admin.py         # команды в ЛС
└── middlewares/
    └── deps.py          # инжектит settings/db/filters в хендлеры

scripts/
└── init_db.py           # ручная инициализация БД

deploy/
├── asvet-antispam.service   # systemd unit
└── install.sh               # авто-установка на Ubuntu/Debian

Dockerfile, docker-compose.yml
```

## Поток данных

### При вступлении нового участника

1. Telegram шлёт `service message` (новые участники)
2. `captcha.py::on_new_members`:
   - Если это бот → бан без разговоров
   - Если аккаунт молодой → бан с указанием причины
   - Иначе → шлёт сообщение с inline-кнопкой «Я не робот», сохраняет челлендж в БД
3. Фоновая таска `captcha_sweeper` каждые 10 сек проверяет истёкшие челленджи и кикает тех, кто не нажал

### При обычном сообщении

1. `messages.py::on_message` пропускает админов и вайтлист
2. `spam.match()` — если есть паттерн → удалить + инкремент
3. `flood.check()` — если перебор → временный бан на 5 мин
4. Иначе сообщение живёт

### При админ-команде (только в ЛС)

1. `admin.py::*_cmd` — простая логика, идёт в БД + телеграм-вызов
2. Вся работа идёт через `db.Database`, никаких прямых SQL в хендлерах

## Схема БД

| Таблица | Что хранит |
|---|---|
| `captchas` | активные челленджи (user_id, message_id, deadline) |
| `bans` | баны (временные и постоянные, `until=0` значит навсегда) |
| `flood_log` | скользящее окно последних N секунд для антифлуда |
| `whitelist` | user_id, освобождённые от всех фильтров |
| `stats` | счётчики: `bans`, `deleted`, `captcha_fails`, `flood_warns`, `total_events` |
| `deleted_msgs` | журнал удалённых сообщений (msg_id, user_id, ts) |

Все таблицы создаются при `Database.init()` через `CREATE TABLE IF NOT EXISTS`. Миграций нет — если меняешь схему, либо добавляй новые таблицы, либо делай `rm data/bot.db` (потеряешь баны и вайтлист).

## Как расширять

### Добавить новый спам-паттерн

Просто допиши в `.env` ещё один `(?i)что-то` через `||`. Перезапусти бота — паттерны перечитываются на старте.

### Добавить новую админ-команду

1. В `bot/handlers/admin.py` добавь `@router.message(Command("новая"))`
2. Внутри используй `db`, `bot`, `settings` (придут через DI)
3. Пропиши команду в `/help`

### Добавить новый тип фильтра

1. Создай `bot/filters/my_filter.py` с dataclass-классом
2. Создай инстанс в `__main__.py::main()`
3. Передай в `DependencyMiddleware`
4. Используй в нужном хендлере

### Сменить способ хранения (например, на Postgres)

`bot/db.py` инкапсулирует все SQL-запросы. Меняешь там — хендлеры не трогаются. Просто создай новый класс `Database` с тем же интерфейсом, но с `asyncpg` вместо `aiosqlite`.

## Известные ограничения

- **Оценка возраста аккаунта** — по `user_id >> 22` (snowflake). Точность ± несколько дней. Реальную дату регистрации Telegram Bot API не отдаёт.
- **Username в `/ban`** — нужно либо reply, либо числовой `user_id`. Резолв по `@username` без явного вызова `getChat` не работает.
- **Один инстанс.** Если запустить две копии — будут дубли капчи и спам-фильтра. Горизонтальное масштабирование требует переезда на webhook + load-balancer.
- **Логи только в stderr/stdout.** В проде Coolify/journalctl это подхватывает. Если нужны файловые логи — добавь `logging.FileHandler` в `__main__.py::_setup_logging`.
